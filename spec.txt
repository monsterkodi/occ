
name: ocls
folder: ~/s/ocls
language: javascript
dependencies: none
purpose: list, dump and modify opencode v2 sessions
focus: ease of use; colored, nicely layouted and human readable output
usage:

ocls -h|--help               - prints help text with available commands
ocls ls [id...]              - prints session table
ocls cat [id...]             - shows session conversation
ocls log [id...]             - shows full history including tool calls
ocls shell [id...]           - shows shell commands with their output
ocls del id [id...]          - deletes sessions after a confirmation prompt
ocls dump [id...]            - dumps session to text file (uncolored)

cat is log without the tool blocks; shell is log filtered to shell calls.

log blocks:

> user            user message
> agent <mode>    agent message; … continues a run across tool blocks
$ <tool>          tool call
$ <tool> result   tool output, or the error message
$ <tool> exit <n> nonzero exit, the only failure signal a shell call has

session table columns: [id] [start] [duration] [turns] [name]

[id] session id without the ses_ prefix, cropped to 6 characters (width 6)
[start] month-day hour:minute (width 11)
[duration] integer plus a single unit letter s|m|h|d|y, max 4 characters (width 4)
[turns] padded number (width 4)
[name] unpadded, but cropped with ellipsis at right edge of terminal

columns are separated by two spaces; the fixed part is 33 characters wide
turns counts user messages that carry text; synthetic and idle messages do not count
sessions with a parent_id (child sessions) are never listed
a session without a title shows NULL
rows are ordered by time_updated ascending, so the most recent session is last
terminal width falls back to 80 when stdout is not a tty
no table header is printed; renderSession() is the shared row renderer

[id..] if provided, filters sessions by ids; defaults to all sessions (except for del)

implementation:

- data retrieval (src/db.js, src/query.js) separated from render code
- render code: pure functions (src/render.js)
- one file per command, in src/
- renderSession() renders the session row and is reused by every command,
  each of which appends its own content beneath the row
- colors are on for a tty unless NO_COLOR is set
- every color decision lives in ROLES in src/style.js, grouped as row, turn,
  tool and del; changing the look means editing that table and nothing else
- c.fg("#rrggbb", text) and c.bg("#rrggbb", text) take an exact 24-bit color,
  accept #rgb shorthand, and nest inside and around the named colors; a
  malformed color throws StyleError rather than silently not applying
- ocls del requires at least one id, there is no --all
- ocls del requires a terminal, and asks "ARE YOU SURE? (yN)" after showing
  the sessions it is about to delete; it opens the db writable with
  PRAGMA foreign_keys ON so session_message, session_pending, session_inbox,
  instruction_entry and instruction_state cascade
- del is the only command that writes, so it is the only one that is not a
  pure function: it takes an io for writing and reading the answer
- tests in separate test folder, run against a generated fixture database
